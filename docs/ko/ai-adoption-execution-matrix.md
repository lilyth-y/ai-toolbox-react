# AI 도입 1페이지 실행 매트릭스

이 문서는 팀/학교가 AI를 실제로 도입할 때 바로 사용할 수 있는 **실행 체크용 1페이지 요약본**입니다.  
목적은 복잡한 이론이 아니라, **지금 무엇을 해야 하고 무엇을 피해야 하는지**를 빠르게 정렬하는 것입니다.

---

## 1) 공통 운영 원칙

### 해야 할 것 (Do)
- 작은 범위(문서/회의/백로그)부터 시작해 성공 사례를 만든다.
- AI 결과는 초안으로 취급하고, 사람 검토를 최종 단계로 둔다.
- 실패 사례를 숨기지 않고 기록해 다음 반복에 반영한다.
- 업무 단위별 책임자를 명확히 지정한다.

### 하지 말아야 할 것 (Don't)
- 처음부터 자동 채점/고위험 의사결정에 바로 연결하지 않는다.
- AI 출력만 믿고 근거 확인 없이 배포하지 않는다.
- 책임자 없이 "누군가 보겠지" 상태로 운영하지 않는다.
- 효과가 불분명한데 도구만 추가하지 않는다.

---

## 2) 영역별 실행 매트릭스

| 영역 | 해야 할 것 (Do) | 하지 말아야 할 것 (Don't) | 담당자 (Owner) | 착수 신호 |
|---|---|---|---|---|
| 수업/업무 설계 | 목표 문장과 산출물 형식을 AI로 초안화 | 목표 없는 자동화 시작 | 교육자/PM | 목표 문서가 매번 제각각일 때 |
| 문서/콘텐츠 제작 | 회의록, 보고서, 공지문 템플릿 자동 생성 | 원문 검증 없이 외부 공유 | 콘텐츠 담당/실무자 | 문서 작성 시간이 반복 과다할 때 |
| 프로젝트 관리 | 회의 후속조치(담당/기한/우선순위) 자동 정리 | 액션아이템 책임자 미지정 | PM/팀 리더 | 회의 후 작업 누락이 잦을 때 |
| 학습 지원/코칭 | 질문 유형별 답변 초안, 오답 패턴 분류 | 학습자에게 단일 정답만 강요 | 교사/멘토 | 반복 질문이 많아 피드백 지연될 때 |
| 개발/연동 | API 호출 규칙, 응답 스키마, 에러 처리 정의 | 예외 처리 없이 데모 우선 개발 | 개발자 | 기능은 되는데 장애 대응이 안 될 때 |
| 운영/거버넌스 | 민감정보 마스킹, 로그 기록, 검토 절차 문서화 | 정책 없이 운영 데이터 축적 | 운영 담당/보안 담당 | 개인정보/민감정보 입력이 시작될 때 |
| 모바일 활용 | 음성/사진 입력 기반 현장 업무 단축 | 데스크톱 UX를 모바일에 그대로 복사 | 모바일 담당/교육자 | 현장 입력이 많고 즉시 대응이 필요할 때 |

## 3) 권장 담당자 구조 (최소 인원 버전)

| 역할 | 책임 범위 | 산출물 |
|---|---|---|
| 프로젝트 오너 (PM/교육담당) | 범위/우선순위/일정 결정 | 주간 계획, 우선순위표 |
| 도메인 오너 (교사/실무전문가) | 결과 품질 검수, 현장 적합성 확인 | 검수 코멘트, 수정 지침 |
| AI 구현 오너 (개발자/자동화 담당) | 프롬프트, API, 자동화 로직 구현 | 구현 문서, 테스트 로그 |
| 운영 오너 (운영/보안) | 정책, 로그, 권한, 사고 대응 | 운영 체크리스트, 이슈 리포트 |

---

## 4) 2주 실행 플로우 (빠른 적용형)

### Week 1: 저위험 고효과 영역
1. 문서 자동화 템플릿 3종 도입
2. 회의 후속조치 자동 추출 도입
3. 담당자별 검토 루프 운영 시작

### Week 2: 구조화와 안정화
1. API/응답 스키마 정리
2. 실패 사례 5건 수집 및 패턴화
3. 운영 정책(검토/로그/민감정보) 문서화

---

## 5) 바로 쓰는 주간 점검 질문

- 이번 주에 AI가 **시간을 실제로 줄인 업무**는 무엇인가?
- 사람이 반드시 직접 본 최종 검토 지점은 어디인가?
- 실패/오류가 반복된 영역은 어디이며, 다음 주에 무엇을 바꿀 것인가?
- 신규 도입보다 "기존 도입 안정화"가 필요한 영역은 어디인가?

---

## 6) 사용법

1. 이번 주에 도입할 영역을 최대 2개만 선택합니다.  
2. 각 영역의 Do/Don't/Owner를 회의에서 확정합니다.  
3. 주말에 점검 질문 4개로 회고하고, 다음 주 항목을 갱신합니다.
