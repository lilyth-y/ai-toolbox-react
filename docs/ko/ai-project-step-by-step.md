# AI로 할 수 있는 일: Step-by-Step 교육 프로젝트 가이드 (재설계본)

이 문서는 **노베이스 학습자도 이해 가능한 흐름**으로, AI 활용 프로젝트를 실제 교육/운영 가능한 형태로 설계한 안내서입니다.  
핵심은 "기능 나열"이 아니라, **측정 가능한 학습성과 + 안전한 운영 + 단계적 확장**입니다.

---

## 0) 이 가이드의 목표와 완료 기준 (측정 가능)

## 0-1. 과정 목표
1. 문서 작성과 프로젝트 관리를 AI로 자동화하는 실무 능력 확보
2. 기존 모델 API 연동을 통해 서비스 기능을 구현하는 능력 확보
3. 주관식 채점 모듈 사례를 통해 모델 활용/개선의 기본 구조 이해

## 0-2. 학습자 성취기준 (수료 기준)
아래 4개를 모두 충족하면 수료로 판단합니다.

| 구분 | 성취기준 | 통과 기준 |
|---|---|---|
| 이해 | 핵심 용어 10개 설명 가능 | 구두/퀴즈 80% 이상 |
| 구현 | Step 1~3 산출물 제출 | 필수 항목 누락 없음 |
| 검증 | 3단계 평가 절차(실행/소규모/전체) 보고 | 각 단계 로그 또는 캡처 제출 |
| 성찰 | 실패 사례와 개선안 문서화 | 최소 3개 리스크와 대응 기록 |

## 0-3. 교육자 운영 성공지표
- 완주율(중도 이탈 없이 Step 3 제출): 70% 이상
- 제출물 충족률(필수 항목 기준): 80% 이상
- 학생 자기효능감 설문(5점 척도): 평균 3.8 이상

## 1) 노베이스를 위한 시작점

### 1-1. 먼저 이해할 핵심 용어 6개
- **프롬프트(Prompt)**: AI에게 내리는 지시문
- **LLM**: 긴 문장을 이해/생성하는 언어 모델
- **워크플로우**: 일을 처리하는 순서(기획 -> 작성 -> 검토 -> 배포)
- **API**: 앱과 AI 서비스를 연결하는 인터페이스
- **파인튜닝(Fine-tuning)**: 특정 문제 성능을 높이기 위한 추가 학습
- **평가지표(Metric)**: 결과 품질을 수치로 검증하는 기준

### 1-2. 프로젝트 운영 원칙
- 처음에는 최고 성능보다 **재현 가능한 절차**를 우선합니다.
- 실험은 **한 번에 변수 하나만** 변경합니다.
- 평가는 반드시 **1단계(실행) -> 2단계(소규모) -> 3단계(전체)** 순서로 진행합니다.

## 2) 카테고리 체계 (기초 -> 심화)

| 순서 | 카테고리 | 핵심 질문 | 대표 산출물 |
|---|---|---|---|
| 1 | 문서 작성 자동화 | AI로 글쓰기/요약을 얼마나 빠르게 할까? | 회의록/보고서 초안 |
| 2 | 프로젝트 관리 자동화 | 작업을 어떻게 구조화하고 추적할까? | 백로그/주간 리포트 |
| 3 | 지식/자료 운영 | 산재된 정보를 어떻게 검색 가능하게 만들까? | FAQ/내부 위키 |
| 4 | 업무 보조 도구 제작 | 반복 업무를 어떻게 줄일까? | 분류기/자동 작성기 |
| 5 | 모델 활용 애플리케이션 | 기존 모델을 서비스와 어떻게 연결할까? | 챗봇/API 기능 |
| 6 | 모델 개발/개선 | 우리 문제에 맞게 성능을 어떻게 개선할까? | 평가 리포트/개선안 |
| 7 | 모바일 AI 활용 (별도 트랙) | 이동 중 AI를 어떻게 활용할까? | 모바일 실습 가이드 |

## 3) 단계별 실행 가이드 (브릿지 포함)

## Step 1. 문서 작성 자동화
### 목표
- 동일 정보를 여러 목적(요약/상세/발표)으로 변환

### 필수 산출물
- 문서 템플릿 3종(회의록/보고서/발표본)
- 프롬프트 템플릿 3종(요약/교정/톤변환)
- 품질 체크리스트 1종(사실성/누락/표현)

### 통과 기준
- 같은 원문에서 3가지 형식 결과를 생성하고, 체크리스트로 자체 검수 완료

---

## Step 2. 프로젝트 관리 자동화
### 목표
- AI로 작업 분해, 우선순위 결정, 리스크 정리

### 필수 산출물
- 태스크 템플릿(목표/완료조건/담당/기한)
- 회의 메모 -> 액션아이템 자동 추출 결과
- 주간 진행 리포트 자동 생성본

### 통과 기준
- 액션아이템 정확도(교사 수동검수 대비): 80% 이상

---

## Step 2.5 (브릿지). 노코드/로우코드 연동 체험
Step 2에서 Step 3으로 넘어갈 때 초보자 이탈을 줄이기 위한 완충 단계입니다.

### 목표
- 코드 작성 부담 없이 "AI 호출 -> 결과 구조화 -> 검토" 흐름 이해

### 필수 산출물
- 입력폼 1개 + 결과 JSON 1개(키: summary, action_items, risk)
- 실패 케이스 2개와 재시도 프롬프트 2개

### 통과 기준
- 잘못된 입력 2종에 대해 재시도 전략을 문서화

---

## Step 3. 기존 모델 API 연동형 서비스
### 목표
- 백엔드/프론트 연결을 통한 실제 기능 구현

### 필수 산출물
- 백엔드: 프롬프트 라우팅, 에러 처리, 요청 로그
- 프론트: 입력/결과/재생성/히스토리 UI
- 운영: 실패 응답 처리 규칙, 기본 안전필터 정책

### 통과 기준
- 정상 케이스 5개, 실패 케이스 3개 테스트 통과

---

## Step 4. 새로운 모델 생성/활용 시나리오
### 예시: 주관식 시험문제 자동 채점 모듈 + 프론트 연동

### 4-1. 문제 정의
- 입력: 학생 주관식 답안
- 출력: 점수 + 근거 코멘트 + 개선 피드백
- 목표: 채점 일관성 향상, 피드백 시간 단축

### 4-2. 데이터 설계
- 기본 스키마: `(문항, 모범답안, 루브릭, 학생답안, 정답점수)`
- 라벨 품질: 최소 2인 교차 검수

### 4-3. 평가 단계 (필수)
1. **1단계(실행 검증):** 파이프라인이 끝까지 동작하는지 확인
2. **2단계(소규모 검증):** 소규모 데이터에서 일관성 개선 확인
3. **3단계(전체 평가):** 전체 데이터 기준 성능 측정

### 4-4. 교육 현장 안전장치 (필수 정책)
1. **Human-in-the-loop 의무화**  
   - AI 점수는 임시 점수이며, 최종 확정은 교사만 수행
2. **이의제기 프로세스**  
   - 학생은 근거 보기 후 재평가 요청 가능  
   - 재평가 시 교사 수동 코멘트를 반드시 남김
3. **허용 오차 임계값**  
   - 사람 채점 대비 편차가 기준값 초과 시 자동 채점 결과는 "참고용"으로 강등
4. **배포 차단 조건**  
   - 편향/환각 리스크가 완화되지 않으면 운영 배포 금지

### 4-5. 프론트 연동 화면
- 교사용: 답안 목록, AI 임시점수, 근거, 수동수정, 최종확정
- 학생용: 최종점수, 피드백, 이의제기 버튼
- 관리자용: 문항별 편차율/재평가율 대시보드

## 4) 교육자 운영안 (차시 단위)

| 차시 | 도입(15%) | 실습(70%) | 회고(15%) | 교사 체크포인트 |
|---|---|---|---|---|
| 1차시 | AI 활용 목표 정렬 | Step 1 수행 | 결과 비교 | 템플릿 완성 여부 |
| 2차시 | 작업 분해 원칙 설명 | Step 2 수행 | 리스크 공유 | 액션아이템 정확도 |
| 3차시 | 브릿지 필요성 안내 | Step 2.5 수행 | 실패 사례 분석 | 재시도 전략 품질 |
| 4차시 | API 연동 구조 설명 | Step 3 수행 | 장애 대응 정리 | 실패 케이스 처리 |
| 5차시 | 공정성/안전성 강조 | Step 4 시뮬레이션 | 윤리 이슈 토론 | Human-in-the-loop 준수 |

### 교육자용 운영 체크리스트

- [ ] "AI 결과는 초안" 원칙 반복 고지
- [ ] 평가 단계(1/2/3단계) 분리 진행 확인
- [ ] 실패 사례를 감점이 아닌 학습 근거로 기록

## 5) 학생 제출물 명세와 루브릭

## 5-1. 제출물 명세
| 단계 | 제출 파일/내용 | 최소 요구사항 |
|---|---|---|
| Step 1 | 문서 3종 + 프롬프트 3종 | 원문 대비 변환 목적이 명확할 것 |
| Step 2 | 액션아이템 추출 결과 + 주간 리포트 | 담당자/마감일 누락 없음 |
| Step 2.5 | 입력/출력(JSON) + 실패 2건 재시도 기록 | 재시도 전후 비교 포함 |
| Step 3 | API 명세 + UI 캡처 + 테스트 로그 | 실패 케이스 3개 포함 |
| Step 4 | 평가 보고서 + 안전장치 정책 문서 | Human-in-the-loop, 이의제기 절차 포함 |

## 5-2. 공통 제출 템플릿
```text
[문제정의]
- 해결하려는 문제:
- 사용자:

[접근방법]
- 사용한 도구/모델:
- 프롬프트 또는 로직:

[검증]
- 1단계 결과:
- 2단계 결과:
- 3단계 결과:

[리스크와 대응]
- 실패 사례 1:
- 실패 사례 2:
- 개선 계획:
```

## 5-3. 평가 루브릭 (100점)
- 문제정의 명확성: 20점
- 구현 완성도: 25점
- 검증 엄밀성(1/2/3단계 분리): 25점
- 리스크 분석과 대응: 20점
- 문서 품질(재현 가능성): 10점

## 6) 모바일 환경 AI 활용 (별도 트랙)

모바일은 "짧은 입력, 빠른 확인, 현장 대응"에 강점이 있습니다.

### 6-1. 모바일 우선 학습 시나리오
- 음성 -> 텍스트 회의록 변환
- 이동 중 요약 확인 및 승인
- 사진 기반 OCR 정리
- 현장 질의응답(매뉴얼 검색)

### 6-2. 모바일 트랙 산출물
- 모바일 전용 프롬프트 템플릿(짧은 입력형) 5개
- 3줄 요약 -> 상세보기 구조의 화면 시안
- 개인정보 마스킹 정책 체크리스트

## 7) 예상 교육 결과 (교육자/학생 관점)

## 7-1. 교육자 관점
- 장점: 수업 결과를 정량 지표로 추적 가능, 평가 일관성 향상
- 주의: Step 4에서는 반드시 교사 최종 확정 정책을 유지해야 함

## 7-2. 학생 관점
- 장점: Step 1~2에서 즉시 성취감 확보, Step 2.5로 난이도 점프 완화
- 주의: "AI 정답 의존"이 아닌 "검증 가능한 결과" 중심으로 학습해야 함

## 7-3. 기관/프로그램 관점
- 기대효과: 문서 생산성 향상, 프로젝트 운영 표준화, 책임 있는 AI 활용 문화 정착
